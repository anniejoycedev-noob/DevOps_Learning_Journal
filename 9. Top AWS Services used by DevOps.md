<h2 id="section-1">1. Introduction to AWS Services for DevOps</h2>

<h3>Definition of AWS & The Service Model</h3>
<ul>
  <li><b>AWS (Amazon Water Services / Amazon Web Services):</b> A cloud provider that falls into the category of Infrastructure as a Service (IaaS) and Platform as a Service (PaaS), with the main concept of making life easy by providing products and applications in a service model.</li>
  <li><b>The Service Model Philosophy:</b> Designed to eliminate heavy operational burdens (e.g., kubernetes installation, deployment, and management is an overhead, so AWS created Kubernetes as a service where everything underneath is taken care of by AWS).</li>
  <li><b>Scope:</b> AWS has close to 200+ services (around 210 at the time of the video). A DevOps engineer does not need to worry about all of them (e.g., machine learning services unless working on an ML project); focus must remain squarely on <b>automation</b> and <b>efficiency</b>.</li>
</ul>

<h2 id="section-2">2. Core Compute & Storage Services (EC2 vs. Lambda Deep-Dive)</h2>

<h3>Essential Services Covered</h3>
<ul>
  <li><b><code>EC2 (Elastic Compute Cloud)</code>:</b> A compute service that comes by default with storage or default volumes, used to deploy applications, run dynamic workloads, and expose applications to the external world.</li>
  <li><b><code>Lambda (Serverless Compute)</code>:</b> A serverless compute service used for short actions and short functionalities that can be executed and teared down automatically without creating an EC2 instance.
    <ul>
      <li><b>Key Difference vs. EC2:</b> In an EC2 instance, you deploy your application and explicitly choose/manage a server (like selecting Ubuntu, Red Hat, or CentOS). In contrast, AWS Lambda functions are created and paid for automatically—AWS takes your code, automatically creates an underlying instance for the execution, runs the code, and tears down the instance once execution is finished without asking you to provision an operating system.</li>
      <li><b>Why Lambda over EC2 for short tasks?:</b> If 100 developers are creating EBS volumes at once, it is a waste of time to spin up 100 EC2 instances just to run a short script. Instead, running them as Lambda functions saves time and resource overhead.</li>
    </ul>
  </li>
  <li><b><code>EBS (Elastic Block Store)</code> / Volumes:</b> Persistent block storage volumes attached to EC2 instances. Vital when applications keep creating files or databases are deployed, allowing you to store info into volume mounts, take snapshots, take backups, and reattach them.</li>
  <li><b><code>S3 (Simple Storage Service)</code>:</b> A cheap, extendable storage service widely used when applications read content from external sources (like Excel sheets or files) or write humongous data/Json/Yaml files. S3 is encrypted by default (data stored in S3 has mandatory AWS-defined encryption).</li>
</ul>

<h2 id="section-3">3. Networking & Security Fundamentals</h2>

<h3>Networking Components</h3>
<ul>
  <li><b><code>VPC (Virtual Private Cloud)</code>:</b> Secures your AWS resources. Core components include:
    <ul>
      <li><b>CIDR Blocks:</b> Subnet ranges.</li>
      <li><b>Security Groups:</b> Firewalls controlling traffic.</li>
      <li><b>Inbound & Outbound Traffic Rules:</b> Explicit traffic regulations.</li>
    </ul>
  </li>
</ul>

<h3>Security & Identity Management</h3>
<ul>
  <li><b><code>IAM (Identity and Access Management)</code>:</b> Manages user permissions and access control (e.g., configuring policy rules so a developer only has access to ec2 instances, or read-only access to S3/EBS).</li>
  <li><b><code>KMS (Key Management Service)</code>:</b> A Key Management Service used to store secrets, manage/rotate certificates, and handle encryption keys for S3 and EBS volumes.</li>
</ul>

<h2 id="section-4">4. Monitoring, Observability & Auditing</h2>

<h3>Monitoring vs. Auditing Services</h3>
<ul>
  <li><b><code>CloudWatch</code>:</b> A monitoring and observability service that constantly tracks every action taking place on AWS (e.g., tracking when a developer creates an S3 bucket or EBS volume, or when an EC2 instance reaches CPU/memory thresholds).</li>
  <li><b><code>CloudTrail</code>:</b> Enables operational and risk auditing by recording API activity logs and preserving them for specific durations (e.g., last 30 days or six months).</li>
  <li><b><code>AWS Config</code>:</b> A guardrail service that monitors resource configurations to ensure compliance (e.g., checking if an EBS volume was created unencrypted).</li>
</ul>

<h2 id="section-5">5. CI/CD & Build Services</h2>

<h3>AWS Native Automation Suite</h3>
<ul>
  <li><b><code>AWS CodePipeline</code>:</b> A pipeline service similar to Jenkins that defines event targets, nodes, and workflow actions.</li>
  <li><b><code>AWS CodeBuild</code>:</b> A fully managed build service that takes care of compiling code, running tests, and providing software packages/artifacts (like war or jar files).</li>
  <li><b><code>AWS CodeDeploy</code>:</b> Takes care of deploying built artifacts and applications onto EC2 instances or on-premises servers.</li>
  <li><b>Strategic Trade-off:</b> Recommended if you are completely on AWS; however, if you are multi-cloud or might move to Azure later, using these AWS-restricted build services is not recommended.</li>
</ul>

<h2 id="section-6">6. Containers & Logging Infrastructure</h2>

<h3>Container Orchestration</h3>
<ul>
  <li><b><code>EKS (Elastic Kubernetes Service)</code>:</b> A managed Kubernetes service provided by AWS. If you know Kubernetes fundamentals on-premises, learning EKS takes very little effort.</li>
  <li><b><code>ECS (Elastic Container Service) vs. EKS</code>:</b>
    <ul>
      <li><b>ECS:</b> An AWS proprietary container orchestration solution built by Amazon.</li>
      <li><b>EKS:</b> A managed open-source Kubernetes service provided by AWS.</li>
    </ul>
  </li>
  <li><b>AWS Fargate:</b> Container service used without managing underlying Kubernetes infrastructure.</li>
</ul>

<h3>Logging & Cost Management</h3>
<ul>
  <li><b><code>ELK Stack (Elasticsearch, Logstash, Kibana)</code>:</b> Used for efficient logging and search mechanisms to aggregate microservice logs and query common errors over time.</li>
  <li><b><code>Billing and Costing Service</code>:</b> Tracks organizational spending and financial data to see how much money is spent on EC2, S3, or EBS over 30 or 90 days.</li>
</ul>

<h2 id="section-7">7. Simple Analogy & Real-Life Scenario (EC2 vs. Lambda)</h2>

<h3>Easy-to-Understand Analogy: Renting a Car vs. Booking a Taxi</h3>
<ul>
  <li><b>EC2 is like renting a car for a whole month:</b> You pick the model (OS like Ubuntu/Red Hat), you pay for the full time it sits in the parking lot whether you drive it or not, and you are responsible for maintaining it.</li>
  <li><b>Lambda is like booking an instant ride-share taxi only when you need to go somewhere:</b> You don't own the car, you don't worry about engine maintenance or gas, it shows up instantly the moment you call it (an event triggers it), drives you for that short trip, and disappears once you step out. You only pay for the exact seconds of that trip.</li>
</ul>

<h3>Real-Life Scenario: Enforcing Security Compliance Automatically</h3>
<ul>
  <li><b>The Problem:</b> Company policy dictates that all EBS volumes created by developers must be encrypted. However, a developer accidentally creates an unencrypted EBS volume.</li>
  <li><b>The Automation Flow:</b> 
    <ol>
      <li><b>CloudWatch</b> notices the event log that a new EBS volume was created without encryption.</li>
      <li>Instead of keeping a heavy server (EC2) running 24/7 just to watch for this mistake, an event triggers an <b>AWS Lambda</b> function instantly.</li>
      <li>Lambda executes a short script to check the volume, applies the encryption rules or fires off an alert email to the developer explaining compliance rules, and then automatically shuts down right after.</li>
    </ol>
  </li>
</ul>
